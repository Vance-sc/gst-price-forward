# Authorship check

Every commit in this repo is authored and committed as
`Vance Boucher <vance@socalbusinessgroup.com>`, and nothing in the history,
branch names or files credits a tool or bot. This check enforces that in two
places:

- **Local git hooks** (`.githooks/`) stop a bad commit or push on your machine.
- **A pull request check** (`.github/workflows/authorship-check.yml`, job
  `authorship-check`) runs the same rules on GitHub. Local hooks can be skipped
  with `git commit --no-verify` or `git push --no-verify`; the PR check cannot.

Rules live in two files:

- `.authorship-check.conf` – allowed identity, blocked branch prefixes and the
  allowlist. This is the file you tune per repo.
- `tools/authorship-check.patterns` – the blocked wording itself.

## What it blocks

| Where | Blocked |
|---|---|
| Author / committer | Anything other than the allowed identity (name and email must match exactly). The one exception: commits you made in the GitHub web editor, where the author is you and the committer is `GitHub <noreply@github.com>`. |
| Branch names | Names starting with any `block_branch` prefix in the conf. |
| Commit messages, PR title and description | `Co-authored-by:` and `Signed-off-by:` trailers naming anyone but you; "Generated with" / "Generated by" lines; the robot emoji; tool and vendor names from the patterns file. |
| Added lines in files | The robot emoji; "Generated with/by" followed by a tool name; `Co-authored-by:`; tool and vendor names from the patterns file. Only lines added by the commit or pull request are checked, so existing text elsewhere in a file does not trip it. |

Not blocked: ordinary words such as `cursor` (database cursors), the word `AI`,
and identifiers such as `ai_review`. Genuine code use of a tool – SDK imports,
model ids, API key variable names, API hostnames, dependency entries, and the
tools' own config files – is allowed through the allowlist in the conf.

## Install the local hooks (once per clone)

```sh
sh tools/install-hooks.sh
```

This sets `git config core.hooksPath .githooks`. Works the same in Git Bash on
Windows, macOS and Linux; it only needs git and the standard shell tools.
If the repo already uses the pre-commit framework, the script prints how to
add the entries from `tools/pre-commit-hooks.yaml.snippet` instead.

## Fixing a failure

The check prints what it found and the commands to fix it. In short:

- **Wrong name or email**
  `git config user.name "Vance Boucher"` and
  `git config user.email "vance@socalbusinessgroup.com"`, then commit again.
  For commits already made: `git commit --amend --no-edit --reset-author`
  (last commit) or
  `git rebase -r <base> --exec "git commit --amend --no-edit --reset-author"`
  (several), then `git push --force-with-lease`.
- **Branch name** – `git branch -m <old> <new>`. If already pushed:
  `git push -u origin <new>` and `git push origin --delete <old>`, then open the
  pull request from the new branch.
- **Commit message** – `git commit --amend` and delete the listed lines (for
  example a trailer at the bottom). For older commits, `git rebase -i <base>`
  and mark them `reword`.
- **Added lines** – edit the line and `git add` the file again.
- **PR title or description** – edit it on GitHub; the check re-runs.

## Allowing genuine code use

Add one line per entry to the bottom of `.authorship-check.conf`
(comments go on their own line, starting with `#`):

```
# skip a whole path
allow_path docs/vendor-notes/**
# remove matching text from any line before checking
allow_line my_sdk_client\.
# same, only in files matching the glob
allow_line_in settings.py _model[ ]*=
```

`allow_line` patterns are lowercase extended regular expressions. The matching
text is removed from the line first; the line passes only if nothing blocked is
left. To see what an existing repo already contains, run the report-only scan:

```sh
sh tools/authorship-check.sh scan-tree
```

## Making the PR check required

The workflow runs on every pull request, but GitHub only enforces it once the
repo owner makes it required: **Settings > Branches** (branch protection rule)
or **Settings > Rules > Rulesets**, turn on "Require status checks to pass" and
add `authorship-check`.

## Line endings on Windows

Keep the check's files LF-only. Those rules are in `.gitattributes`.

## Notes

`.github/workflows/keepalive.yml` pushes a heartbeat commit authored by
`github-actions[bot]` directly to `main`, not through a pull request. The
pull request check does not see those commits, so no allowlist entry is
needed for them.
